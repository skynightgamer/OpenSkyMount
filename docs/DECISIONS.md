# Decision log

| # | Decision | Reason | Alternatives considered |
|---|---|---|---|
| D1 | Python + FastAPI backend, React + TS + three.js frontend, one process | Matches the proposed stack, simple local deployment, typed | Node backend (weaker astronomy libraries), microservices (unneeded) |
| D2 | Skyfield + DE421 (`skyfield-data`) for astronomy, offline | Accurate, MIT, no network at runtime | Astropy (heavy, IERS downloads) is kept as a test-only cross-check |
| D3 | Server-authoritative simulation and control | One source of truth for all devices; the same controller drives real hardware | Simulating in the browser (would desync clients and duplicate logic) |
| D4 | Driver API in axis coordinates, astronomy and tracking on the host | Firmware stays tiny and testable; the simulator and hardware are interchangeable | Firmware-side astronomy like OnStepX (supported later through an adapter) |
| D5 | Position + rate setpoints, extrapolated by the axis between commands | Smooth tracking with sparse setpoints and robust to latency | Pure velocity streaming (drifts), position-only (stair steps) |
| D6 | Setpoints refer to the start of each control interval | Fixed a one-interval lead (16″ error) found by the headless demo; regression test added | — |
| D7 | Fixed-step control in simulation time; 1 s steps in smooth tracking, 0.2 s physics steps in steady state | Time acceleration up to 3600× without behaviour change; about 8× faster tests | Variable-step integration |
| D8 | Multi-turn azimuth ±270° with automatic unwind | Realistic cable management; avoids long slews across north | Unlimited azimuth (needs a slip ring) |
| D9 | Solar GoTo refused by default and always refused off-simulator; 15° exclusion zone | Safety requirement | Allow with a warning (rejected) |
| D10 | Single control lease + per-session seq numbers; E-stop/Stop from anyone | Prevents conflicting or stale commands; safety first | Multi-controller merging |
| D11 | Dead-man timers in wall time | Must not expire faster at high simulation rates | Simulation time |
| D12 | Catalog from d3-celestial (BSD-3), committed as compact JSON | License-compatible, offline, includes names and constellation lines | HYG (CC BY-SA, share-alike), Stellarium skycultures (GPL) |
| D13 | Own canvas sky map (stereographic) instead of embedding Stellarium Web Engine | AGPL/GPL incompatibility with MIT, size, control over interaction | Stellarium Web Engine, d3-celestial runtime |
| D14 | OSM/1 ASCII line protocol + fake firmware | Trivial to implement on an ESP32; executable spec; testable over TCP | JSON over serial (heavier), immediate OnStepX dependency (GPL firmware, different model) |
| D15 | Plate solving with cedar-solve/tetra3 as an optional extra, installed `--no-deps` with a numpy-2 shim | Apache-2.0, bundled database, fast; its version pins block Python 3.13 | astrometry.net (GB indexes), writing a custom solver (discouraged) |
| D16 | MIT license | Compatible with all bundled data and dependencies | GPL (would allow embedding Stellarium/OnStepX code, but limits reuse) |
| D17 | No UI component library | Small bundle, custom dark astronomy look | MUI/Chakra (heavier) |
| D18 | Berlin as the default site | A neutral, valid default; the user sets their own site in Settings | Geolocation required (rejected: must be optional) |
| D19 | (superseded by D25) UI styled as observatory instrument panel: warm graphite, amber backlight accent, condensed engraved labels, mono LCD-style readouts, hairline rules instead of floating cards; fonts bundled locally | Replace generic dashboard look with one grounded in the subject; keep the app offline-capable | Component-library defaults, web-font CDN |
| D20 | "Red light" mode via an SVG luminance→red colour matrix on the whole document (covers canvas and WebGL) | Astronomers use red light to keep dark adaptation; pure red output, no green/blue | CSS sepia/hue-rotate chain (left yellow tints) |
| D21 | Star catalog = Hipparcos-2 astrometry (I/311) + d3-celestial magnitudes/names, to V = 8; served in two tiers (≤ 6.5 always, 6.5–8 on zoom) with positions propagated to the current year | Proper motion matters (Arcturus moved > 60″ since 1991); CDS was unreachable, so the public data was taken from the MIT `hipparcos-catalog` package | HYG (CC BY-SA), d3 positions without motion |
| D22 | Pointing model = axis zero offsets + base tilt (rotation about North/East), Gauss–Newton fit; tilt only from ≥ 3 points; Sync and plate solving both add points | Matches the dominant errors of a DIY alt-az mount; 1–2 points cannot separate tilt from offsets | TPoint-style full model (cone, non-perpendicularity) left for later |
| D23 | Observing planner score: time above limit (cap 6 h) ×1.5 + peak altitude ×0.8 + brightness ×2 + type weight (planet +0.8, Moon +0.5, star −0.5) | Pure "hours above" put faint circumpolar objects first; small optics favour bright showpieces | Surface-brightness based ranking (needs data we do not have) |
| D24 | Field rotation reported as ω·cos φ·cos A / cos h (= −dq/dt of the parallactic angle) | Standard alt-az formula; sign convention locked by a test, exposure limits use the magnitude | — |
| D25 | Plain desktop-tool UI: system font, sentence case, neutral greys, one blue accent, red only for E-STOP; no bundled fonts, no letter-spaced caps, no glowing lamps. Status bar uses fixed grid tracks and fixed-width values | User found the D19 styling generic/"AI-looking" and the status bar moved while values changed | Keep D19 and tweak colours |
| D26 | LAN password: one shared password (CLI/env), in-memory session cookie (HttpOnly, SameSite=Strict), Bearer header for scripts, 5 failed logins per minute per address; `/api/estop` stays open | Keeps casual LAN users away from the controls with minimal setup, while E-stop stays reachable from every device (safety rule) | Per-user accounts; token in the URL (leaks via history); gating E-stop behind the login |
| D27 | Angle format and time zone are per-device browser preferences, not server config | Several devices may want different views; changing them must not need control authority | Server-side setting broadcast to all clients |
| D28 | GitHub Actions CI: backend on Python 3.11 (minimum) and 3.13 with the optional extras, frontend checks and build, browser E2E with Playwright 1.63 (installed `--no-save`, not a package.json dependency); `scripts/e2e.sh` is shared by CI and `scripts/test.sh --e2e` | Same commands locally and in CI; the cloud container's pre-installed Playwright keeps working | Playwright as a devDependency (would pull a second browser build into local setups) |
| D29 | Alpaca device built into the main server (same port, `/api/v1/telescope/0`), on by default, `--no-alpaca` to disable; discovery responder bound to the server's listen address | Alpaca is an HTTP API like ours; one process, one port, one auth scheme. Binding discovery to the listen address keeps a localhost-only server invisible on the LAN | Separate Alpaca process/port (more setup, a second control path) |
| D30 | Alpaca clients are ordinary sessions under control authority: auto-take control only when free, never by force; `AbortSlew` accepted from everyone | Keeps one controller at a time (D10); a background program must not silently override the person at the UI, and stopping must always work | Alpaca bypassing authority; Alpaca always forcing control |
| D31 | Alpaca coordinates = `equTopocentric` (apparent of date, "JNow"); converted to ICRS by iterating Skyfield's forward apparent-place calculation | The most common system for amateur mounts and what N.I.N.A. sends by default; the iteration reuses the tested forward path and converges to < 1 mas | equJ2000 (clients would still convert); a separate precession/nutation/aberration implementation |
| D32 | No Alpaca `MoveAxis` yet | OpenSkyMount's manual motion needs a refresh every second (dead man, D11); Alpaca `MoveAxis` runs until told to stop. Needs its own safe design (e.g. tie to the client's polling) | Implementing it without a dead man (rejected: relaxes a safety rule) |
| D33 | Alpaca deviations: coordinate slew/sync do not require `Tracking=true`; `Tracking=true` tracks the current direction and is refused below the altitude limit | Tracking is tied to a target on this mount and cannot always be enabled first; refusing is honest, faking tracking is not | Strict spec behaviour (would block GoTo from the park position in some directions) |
